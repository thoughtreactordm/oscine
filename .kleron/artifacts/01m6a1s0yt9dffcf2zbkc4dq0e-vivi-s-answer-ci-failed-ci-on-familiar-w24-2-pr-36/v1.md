The failure comes from Familiar's W24-5 test code, not a flake. It breaks on Windows only, and it won't go away on a re-run.

**What failed.** Only one thing went wrong: all 4,951 tests passed, and the error was in the cleanup step of the `the query process` suite. At `tests/main/mcp/queryLibrary.test.ts:306-311`, `afterAll` calls `host.close()` and `harness.dispose()` and then immediately deletes the temp folder with `rmSync(dir, …)`. But `dispose()` in `tests/main/mcp/queryProcess.ts:53` only *sends* `SIGKILL` to the forked query worker. It doesn't wait for the worker to exit. On Windows the worker still has `library.db` open when the delete runs, so Windows refuses it with `EPERM`. Linux lets you delete open files, which is why ubuntu and Familiar's local gate (3 of 3 passes) never saw it.

**What would fix it** (tests only, no product code):
1. Make `QueryProcessHarness.dispose()` async: kill each live child, wait for its `exit` event with a short timeout, and only then delete the worker bundle folder.
2. Make `afterAll` in `queryLibrary.test.ts` async: `await harness.dispose()`, close the database, then `rmSync(dir, { recursive: true, force: true, maxRetries: 5, retryDelay: 100 })` as a backstop.
3. Make the same change in `tests/main/mcp/readTools.test.ts:299`, which uses the same harness and can hit the same race.
